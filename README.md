Практические артефакты по инфраструктуре: runbook развёртывания сервера и автоматизация процесса, которую я довёл до рабочего инструмента.

## На чём это построено

**Debian 12/13.** Для бюджетных VPS выбрал Debian, а не Ubuntu: меньше потребление памяти в простое, меньше фоновых сервисов, стабильнее на 512 МБ. Проверялось на практике, а не по обзорам.

**Один процесс — один публичный адрес.** При лимитированном трафике так проще учитывать нагрузку и ограничивать соединения, чем разбираться с общим пулом.

## Ключевые решения, которые стоит объяснить

### Runbook

- **Не подменять `sources.list` на чужой релиз.** Если провайдер отдаёт устаревший образ — переустанавливать, а не подменять репозитории. Подмена даёт «франкенштейна»: зависимости не сходятся, `apt upgrade` ломает пакеты.
- **Не закрывать текущую SSH-сессию, пока новая не проверена** — иначе останется только консоль провайдера.
- **Четыре проверки после развёртывания:** порт слушает, сервис жив, выход в интернет есть, внешний адрес тот, который ожидался.
- **Правило «сначала бэкап конфига, потом правка».** Откат должен быть в одну команду.

### Установщик

- **`policy-rc.d` на время установки пакета.** Без этого postinst поднимает сервис с дефолтным конфигом — получается гонка «сервис запущен раньше конфига».
- **Положительный контроль до негативного.** `curl` с кодом 97 означает и «сработало правило блокировки», и «не прошла авторизация». Поэтому сначала доказывается, что выход наружу работает с этими же кредами, и только потом код 97 трактуется как блокировка. Иначе проверка врёт.
- **Пароль резервируется на диск сразу после смены**, до остальных шагов: если прогон упадёт посередине, доступ не потеряется.
- **Один `apt-get update` на сервер** и ровно один фолбэк на сборку из исходников.

## Известные ограничения

- Нет rate limit на порту прокси — при публичном порте закрывается правилом `nftables` или `fail2ban`.
- Пересборка выполняется на каждом сервере. Для парка правильнее один раз собрать `.deb` (`checkinstall`) и раздавать его через `dpkg -i`.
- `DenyUsers` пишется в `sshd_config.d`; если в `sshd_config` нет директивы `Include`, файл не применяется — это надо проверять.
